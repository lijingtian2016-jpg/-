# Supabase 邮箱密码注册登录设计

## 目标

为“纸片人男友”增加可供真实用户使用的邮箱密码注册、登录、会话保持和退出登录能力，替换当前仅依赖浏览器 `localStorage` 的昵称演示登录。

首版不保存聊天记录，不强制验证邮箱，不提供忘记密码功能，也不收集昵称或其他个人资料。

## 当前状态

- 项目使用 Next.js 14 App Router、React 18 和 TypeScript。
- `LoginScreen` 当前只收集昵称。
- `AuthContext` 将昵称写入 `localStorage`，没有服务端身份验证。
- 首页根据客户端 `AuthContext` 决定展示登录页、角色选择页或聊天页。
- 聊天、图片和语音 API 当前均为模拟实现。

## 选择的方案

采用 Supabase Auth 的邮箱密码认证，并使用 `@supabase/ssr` 在 Next.js 浏览器端和服务端之间同步 Cookie 会话。

选择这一方案的原因：

- Supabase 托管密码哈希、账号与会话安全，避免自建密码系统。
- Cookie 会话可以被 Next.js 服务端识别，方便以后保护 API。
- 首版实现范围小，同时保留邮箱验证、密码重置和云端数据的扩展路径。

不采用的方案：

- 纯浏览器端 Supabase 会话：实现更简单，但后续服务端鉴权扩展较差。
- Auth.js 配合 Supabase：对当前只有邮箱密码的需求过重。
- 自建账号密码系统：安全责任和维护成本不合理。

## 功能范围

### 包含

- 邮箱 + 密码注册。
- 邮箱 + 密码登录。
- 密码确认与基础表单校验。
- 刷新页面后保持登录状态。
- 退出登录。
- 登录和注册模式切换。
- 加载、成功和错误反馈。
- 中文友好错误提示。
- Vercel/Supabase 环境变量配置说明。

### 不包含

- 邮箱强制验证。
- 忘记密码或重置密码。
- 昵称、头像、生日或性别。
- Google、GitHub 等第三方登录。
- 聊天记录、角色选择或用户资料的云端保存。
- 本轮对现有聊天、图片和语音 API 增加强制鉴权。

## 架构

### Supabase 客户端边界

- 浏览器客户端：供登录、注册、退出和读取当前会话使用。
- 服务端客户端：供 Server Components、Route Handlers 和 Middleware 读取会话使用。
- Middleware：刷新 Supabase 认证令牌，并把更新后的 Cookie 写回响应。

公开环境变量：

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

客户端和仓库中不得出现 `SUPABASE_SERVICE_ROLE_KEY`。

### 认证状态

用真实 Supabase 用户替换现有 `{ name: string }` 本地用户。认证 Provider 负责：

- 首次加载当前会话。
- 订阅认证状态变化。
- 暴露当前用户、加载状态、登录、注册和退出方法。
- 在组件卸载时取消订阅。

登录状态不再写入 `localStorage`。Supabase SDK 通过 Cookie 管理会话。

### 页面保护

- 未登录：展示认证页面。
- 已登录且未选择角色：展示角色选择页。
- 已登录且已选择角色：展示聊天页。
- 初次会话恢复期间：展示现有加载页，避免登录页闪烁。

首版保留当前单页切换结构，不额外引入 `/login` 和 `/register` 路由。

## 页面与交互

采用已确认的“A：居中卡片”方案：

- 粉色柔和渐变背景。
- 居中的白色圆角卡片，桌面端最大宽度约 400px。
- 品牌标题“纸片人男友”和欢迎文案。
- 移动端优先，保留足够触控区域和键盘可达性。

### 登录模式

- 邮箱输入框。
- 密码输入框。
- “登录”主按钮。
- “还没有账号？立即注册”切换入口。

### 注册模式

- 邮箱输入框。
- 密码输入框。
- 确认密码输入框。
- “注册”主按钮。
- “已有账号？返回登录”切换入口。

### 退出入口

角色选择页和聊天页右上角显示退出按钮。退出成功后清除认证状态并返回认证页。

## 数据流

### 注册

1. 用户填写邮箱、密码和确认密码。
2. 客户端完成格式校验。
3. 调用 Supabase `signUp`。
4. 成功后根据 Supabase 返回的会话更新认证状态。
5. 在 Supabase 后台关闭强制邮箱验证时，用户直接进入角色选择页。

### 登录

1. 用户填写邮箱和密码。
2. 调用 `signInWithPassword`。
3. Supabase 返回会话并设置 Cookie。
4. Provider 更新当前用户，首页进入角色选择页。

### 会话恢复

1. 页面加载时读取当前会话。
2. Middleware 刷新临近过期的令牌。
3. Provider 监听认证事件并保持 UI 同步。

### 退出

1. 调用 Supabase `signOut`。
2. 清除会话 Cookie。
3. 清空当前认证用户并返回认证页。

## 校验与错误处理

- 邮箱必须符合基本格式。
- 密码至少 8 位。
- 注册时两次密码必须一致。
- 请求提交期间禁用按钮并显示加载状态，避免重复提交。
- 错误显示在表单卡片内，不使用浏览器弹窗。
- 将常见 Supabase 错误映射为中文：邮箱或密码错误、邮箱已注册、密码不符合要求、请求过于频繁、网络异常。
- 未识别的错误使用统一兜底文案，并只在开发环境记录安全的诊断信息。
- 不记录密码、令牌或完整认证响应。

## 测试策略

### 单元与组件测试

- 登录/注册模式切换。
- 邮箱格式校验。
- 密码最小长度校验。
- 确认密码不一致。
- 提交中按钮状态。
- Supabase 错误的中文映射。
- 登录、注册和退出成功后的状态变化。

Supabase SDK 调用在组件测试中使用边界 mock；表单行为和认证状态转换使用真实组件逻辑。

- `pnpm install --frozen-lockfile`

- `pnpm build`

### 部署验证

1. 在 Supabase 创建项目并配置邮箱认证。
2. 在 Vercel Preview 环境设置公开 Supabase 环境变量。
3. 部署预览版本。
4. 验证注册、刷新后会话恢复、退出和重新登录。
5. 用户确认预览后再发布生产。

## 安全边界

- 密码只提交给 Supabase Auth，不经过自定义数据库或日志。
- 仅在客户端使用匿名公钥；匿名公钥本身可公开，但数据库仍需 RLS。
- 不把 Service Role Key 放入前端、Git 或 Vercel 的 `NEXT_PUBLIC_*` 变量。
- 本轮登录门禁主要控制页面入口，不宣称已保护现有 API。API 鉴权作为后续独立增强任务。

## 成功标准

- 新用户可以用邮箱和至少 8 位密码注册。
- 已注册用户可以登录。
- 刷新页面后仍保持登录。
- 用户可以从角色选择页或聊天页退出。
- 未登录用户无法进入主应用 UI。
- 不再依赖昵称 `localStorage` 判断登录状态。
- 测试、冻结安装和生产构建通过。
- Vercel 预览部署可完成完整注册登录流程。
